The big picture

LangChain is a framework for connecting language models with data, tools, and application logic. It helps you build a workflow around a model—not just send one prompt and hope.

Simple mental model: a model is the engine; the other components provide its instructions, information, capabilities, and guardrails.

Orchestration

Connect steps, pass data between them, and handle branches or parallel work.

Grounding

Bring in relevant, trusted information instead of relying only on model training.

Action

Let the application call specific functions or services when appropriate.

Reliability

Validate inputs and outputs, track state, and handle errors deliberately.

Component 01

Models: the language engine

LangChain gives applications a common way to call model providers. A model interprets inputs and produces text, structured output, embeddings, or tool-call requests, depending on its capabilities.

Chat models

Take a sequence of messages (system, user, assistant) and produce a response. Use for conversation, summarization, extraction, and reasoning tasks.

Embedding models

Convert text into vectors—arrays of numbers that capture semantic similarity. Commonly used to index and search documents.

Example: ask a chat model

from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="gpt-4o-mini", temperature=0)
reply = model.invoke("Explain embeddings in one sentence.")

print(reply.content)

invoke is a convenient way to run a component once. The provider package, model name, credentials, and supported options depend on the model service you choose.

Temperature, simply: it can influence response variation where the provider supports it. Lower values often suit consistent tasks; it is not a guarantee of correctness.

Choosing a model

  • Match capability to the task: chat, vision, tool calling, long context, or embeddings.
  • Compare latency, cost, quality, context limits, and provider availability.
  • Keep provider-specific configuration at the model boundary so the rest of the workflow can remain reusable.
Component 02

Prompts: instructions the model can use

A prompt is the input sent to a model. In chat applications, it is often a sequence of messages with distinct roles. A prompt template keeps the reusable instructions separate from values supplied at runtime.

Message roleTypical purposeExample
systemSet behavior, boundaries, or style“You are a concise study coach.”
userProvide the request and its data“Explain this paragraph: {text}”
assistantRepresent a prior assistant turn or examplePrevious answer in a conversation

Example: reusable prompt template

from langchain_core.prompts import ChatPromptTemplate

prompt = ChatPromptTemplate.from_messages([
    ("system", "You are a patient science tutor. Use a {style} tone."),
    ("user", "Explain {topic} using one everyday example.")
])

messages = prompt.invoke({
    "style": "friendly",
    "topic": "gravity"
})

The template can be reused for different topics without rewriting the whole instruction. Inputs are values to insert; they are not automatically trustworthy instructions.

Prompting techniques

  • Clear task: say what the model should produce, not only what the subject is.
  • Context: supply relevant facts, audience, and constraints.
  • Few-shot examples: show input/output examples when the desired pattern is hard to explain.
  • Output shape: request a format, then validate it with a parser or schema.
Example instruction: “Summarize the passage in exactly three bullet points for a beginner. Use only details from the passage. If a detail is missing, say so.” This is more actionable than “Summarize this.”
Component 03

Chains and Runnables: connect the steps

A chain is a workflow made from components. In modern LangChain, many components implement the Runnable interface, which gives a consistent way to invoke, compose, batch, or stream work. LangChain Expression Language (LCEL) uses the pipe operator (|) to connect compatible steps.

Example: a compact LCEL chain

from langchain_core.output_parsers import StrOutputParser
from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

prompt = ChatPromptTemplate.from_template(
    "Explain {concept} to a beginner in two sentences."
)
model = ChatOpenAI(model="gpt-4o-mini", temperature=0)
chain = prompt | model | StrOutputParser()

answer = chain.invoke({"concept": "vector search"})
print(answer)

The prompt turns a dictionary into messages; the chat model returns an AI message; StrOutputParser extracts its text. The pipe connects those transformations.

Common workflow shapes

ShapeWhat it doesExample
SequentialRun one step after anotherTranslate → summarize → format
ParallelRun independent branches and collect resultsGenerate a title and keywords together
ConditionalSelect a path based on input or a resultRoute a support question to billing or delivery
Practical tip: use a deterministic chain when the steps are known. Introduce an agent only when the application genuinely needs model-directed choices or tool use.
Component 04

Indexing, retrieval, and RAG

Models do not automatically know private or newly updated documents. Retrieval-Augmented Generation (RAG) searches an external knowledge source and provides relevant passages as context for a model's answer.

RAG building blocks

1

Document loader: reads data and represents it as documents, often with text plus metadata like a source name or page number.

2

Text splitter: breaks long content into chunks. Good chunking keeps related ideas together without making chunks too large to retrieve well.

3

Embedding model: maps each chunk to a vector. Similar meanings tend to have nearby vectors, though this is not a perfect measure of truth.

4

Vector store: stores vectors and associated text/metadata, and supports similarity search. Some systems combine vector and keyword search.

5

Retriever: takes a query and returns relevant documents. It may use similarity, filters, reranking, or other search strategies.

Example: retrieve context before answering

from langchain_core.prompts import ChatPromptTemplate
from langchain_openai import ChatOpenAI

prompt = ChatPromptTemplate.from_template(
    "Answer the question using only the context below. "
    "If the answer is not there, say you do not know.\n\n"
    "Context:\n{context}\n\nQuestion: {question}"
)
model = ChatOpenAI(model="gpt-4o-mini", temperature=0)

# Assume `retriever` has already been created and indexed.
question = "How many days can I return an item?"
documents = retriever.invoke(question)
context = "\n\n".join(doc.page_content for doc in documents)

messages = prompt.invoke({"context": context, "question": question})
answer = model.invoke(messages)
print(answer.content)

This shows the retrieval idea without assuming a specific vector database. The loader, splitter, embedding provider, and vector store setup varies by data source and integration.

RAG is not fine-tuning: RAG looks up information at question time. Fine-tuning changes model behavior through training. RAG is often the better fit for facts that change or need source citations.

Make RAG answers more dependable

  • Keep source metadata and show citations or links when useful.
  • Measure retrieval quality separately from answer quality.
  • Tell the model what to do when retrieved context is insufficient.
  • Protect sensitive documents with access controls before retrieval, not just in the final prompt.
Component 05

Output parsers: turn responses into usable values

Models often return text or message objects. An output parser converts that result into a form your application can use, such as a plain string, a list, or structured data.

String parser

Extracts readable text from a model message. Useful for a simple answer or a user-facing summary.

Structured parser

Maps output to fields such as priority and reason. Validate the result before acting on it.

Example: request structured data

from pydantic import BaseModel, Field
from langchain_openai import ChatOpenAI

class StudyCard(BaseModel):
    question: str = Field(description="A short study question")
    answer: str = Field(description="A concise answer")

model = ChatOpenAI(model="gpt-4o-mini", temperature=0)
structured_model = model.with_structured_output(StudyCard)

card = structured_model.invoke(
    "Make a flashcard about what an embedding is."
)
print(card.question)
print(card.answer)

Structured-output support depends on the model and provider integration. Treat model output as untrusted input: enforce types, check allowed values, and handle validation or provider errors.

Important: a requested JSON shape is not a security boundary. Never execute code, authorize access, or perform a sensitive action just because a model returned a plausible-looking field.
Component 06

Conversation state and memory

A model call is usually stateless: it does not remember a previous call unless your application sends relevant history or retrieves saved information. Conversation state is the data your app carries between turns.

  • Short-term conversation context: recent messages that help answer the current turn.
  • Long-term user/application data: information stored in a database or knowledge store and retrieved when relevant.
  • Workflow state: structured progress and decisions in a multi-step process.

Older LangChain examples may use dedicated memory classes. Current applications commonly manage message history explicitly or use LangGraph for stateful, multi-step workflows. Choose persistence deliberately and follow privacy and retention requirements.

Common misconception: “memory” does not mean the model permanently learns everything a user has ever said. The application has to store, select, and supply information.
Component 07

Tools and agents: let the app take action

A tool is a function or service an application makes available to a model—for example, a unit converter, a database lookup, or a shipping-status API. An agent uses a model to choose whether and when to call available tools.

Example: define a small tool

from langchain.tools import tool

@tool
def convert_km_to_miles(kilometers: float) -> float:
    """Convert a distance in kilometers to miles."""
    return kilometers * 0.621371

A clear name, description, and typed input help the model decide when the tool fits and what arguments to provide. The tool itself should still validate inputs and enforce its own permissions.

Example: make an agent with a tool

from langchain.agents import create_agent
from langchain_openai import ChatOpenAI

model = ChatOpenAI(model="gpt-4o-mini", temperature=0)
agent = create_agent(
    model=model,
    tools=[convert_km_to_miles],
    system_prompt="Help with distance conversions. Use the conversion tool when needed."
)

result = agent.invoke({
    "messages": [{"role": "user", "content": "Convert 10 km to miles."}]
})

Agent APIs and result shapes can vary by LangChain version and integration. Check the documentation for the version installed in your project.

Safety rule: tools have real capabilities. Apply least privilege, validate arguments, limit expensive operations, and require human confirmation for consequential actions such as purchases or deletion.

Chain or agent?

Choose a chain when…Consider an agent when…
The steps are known in advance and should be repeatable.The next step depends on information discovered along the way.
You want fewer moving parts and predictable latency.The model must select among several appropriate tools.
A direct prompt → model → parser flow is enough.You can safely bound tool permissions, retries, and execution time.
Putting it together

Example project: a handbook Q&A assistant

Imagine a chatbot that answers questions from a company's employee handbook. One sensible design is:

  1. Prepare documents: load the handbook, split it into useful chunks, embed them, and store them in a vector store.
  2. Receive a question: validate the user's request and check what documents they are allowed to access.
  3. Retrieve evidence: search the index and keep the most relevant chunks with their source metadata.
  4. Build a prompt: include the question and evidence, and instruct the model to say when evidence is missing.
  5. Call the model: generate an answer grounded in the retrieved text.
  6. Format and display: parse the response and include source references so the user can verify it.
  7. Evaluate: test whether retrieval found the right passages and whether the answer used them faithfully.
